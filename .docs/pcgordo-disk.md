# PCGORDO disk — what filled C:, what was freed, what is left

PCGORDO has a single **Samsung 990 PRO 2 TB NVMe** and a **single `C:` partition** (1861.9 GB).
On 2026-10-14 it was **100 % full with 3.8 GB free** — a state that would have made the MultiSeat
install (see `pcgordo-multiseat-moonlight.md`) risky.

Numbers below come from a one-pass scan of the whole volume with .NET enumeration
(`Directory.GetDirectories`/`GetFiles` in a stack walker, skipping reparse points so the
`AppData\Local\Application Data` junction cannot loop), accumulating bytes per ancestor folder and
the largest files. It ran natively on Windows — `du` over `/mnt/c` (drvfs) is far too slow.
915 888 files / 131 689 dirs in 84 s.

## Compacting the WSL / Docker vhdx: blocked on purpose

`wsl --manage <distro> --set-sparse true` is **refused by WSL 2.6.1**:

```
La compatibilidad con VHD disperso está deshabilitada actualmente debido a posibles daños en los
datos. Para forzar que una distribución use un VHD disperso, ejecute:
wsl.exe --manage <DistributionName> --set-sparse --allow-unsafe
```

`--allow-unsafe` is exactly what it says — Microsoft gated the feature for data-loss reasons — so it
was **not** used. What was tried and what is known:

- **`fstrim -av` as root** (works without a password via `wsl.exe -d Ubuntu -u root --exec`): it
  trims fine, but the vhdx does **not** shrink. Shrinking is what `sparseVhd` exists for.
- **`[experimental] sparseVhd=true`** in `%USERPROFILE%\.wslconfig`: set, WSL restarted, still no
  shrink — the safety gate wins. It was then **removed** again, leaving `.wslconfig` at its original
  content (`[wsl2] networkingMode=mirrored`) so no experimental flag is left behind.
- **`Optimize-VHD`**: not available (no Hyper-V PowerShell module on this box). It needs elevation
  and Hyper-V anyway.
- **`diskpart` → `select vdisk file=…` → `compact vdisk`**: needs **elevation** and the distro
  stopped. Worth trying, but it only reclaims blocks the VHDX knows are unused, so it may not give
  back the full slack.
- **`wsl --export` + `--unregister` + `--import`**: guaranteed to produce a fresh, compact vhdx
  (~73 GB instead of 221 GB) but it is invasive — it needs ~73 GB of temporary space and destroys
  the distro's registration. Only with the user present and after a backup.

Unclaimed slack today: **~148 GB** in `ext4.vhdx` (221.3 GB file, 73 GB used) and **~44 GB** in
`docker_data.vhdx` (52.5 GB, ~8 GB used).

## Note on `.wslconfig`

PCGORDO's WSL runs in **mirrored networking mode**, which is why `pcgordo-wsl` is reachable at the
Windows ZeroTier address (`172.25.209.143:2222`) with `sshd` listening inside the distro. Any edit
to `C:\Users\Manu3\.wslconfig` must preserve `networkingMode=mirrored` or SSH access to the WSL side
disappears.
